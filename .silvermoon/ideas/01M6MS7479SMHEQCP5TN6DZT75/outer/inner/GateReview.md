# 授权代理门限审查

## 审查授权与范围

用户于 2026-11-05 明确接受中文版构想，并授权一个 subagent 实施，由协调 agent 独立负责门限审批和验收。实现与外部结果尚未验收；自主决策不等于提前通过检查。

审查以本 IDEA 的构想、实施契约和部署目标为准。首期仅覆盖 VS Code
Host 与 GitHub/Copilot，必须打通用户授权到实际 AHP 连接的凭据交接，不能用其他进程已经登录来替代，也不能把原生 CLI 的测试回答当成 AHPlex
Turn 执行成功。

## 独立门限

1. **凭据来源与保管**：登录使用受支持的组件和正式交接接口；仅使用明确配置的授权身份，不查询默认编辑器或其他应用的账户。核对环境变量、专用配置目录、OS 凭据库边界，以及状态、错误、日志是否泄露秘密。
2. **连接绑定**：凭据只用于显式选择的 Host/资源；错误身份、认证拒绝、过期、连接重建和并发操作不得形成错误的成功状态、广播授权或 Turn 重放。
3. **运行与契约**：确认用户链接/验证码交互、取消/超时、子进程清理和现有最小API/CLI 行为。运行独立回归、完整仓库检查及安装包冒烟检查，不降低覆盖门槛。

## 外部验收入口

在独立数据目录内，由用户原生授权后，通过候选 AHPlex 实际连接两个显式绑定的 VS
Code
Host。为每个 Host 创建或发现 Session/Chat，提交独立 turnId 和随机响应标记，要求原生
`complete`、精确返回标记且无工具操作。另验证未绑定 Host 不获得授权，以及关闭不影响现有编辑器进程。

这部分只定义协调 agent 的验收关注点，不代替部署阶段的真实执行证据。
