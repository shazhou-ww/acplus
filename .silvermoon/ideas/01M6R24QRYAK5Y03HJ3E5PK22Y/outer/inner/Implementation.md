# Implementation

## Steps

### I-S01: 实现安全的本地配置生成

新增
`ahplex init`，复用配置校验与 CLI 模式；显式输入运行时、工作区与授权配置，私有且排他地创建配置文件，不启动或下载任何后端。

必需参数为 `--runtime-root`、`--copilot-command`、`--workspace`。输出由
`--config` 指定，默认
`ahplex.json`；相对输入基于调用目录。显式配置档、预期账号、数据目录、Node、API/daemon 端口均为有界可选项。重定向或
`--json` 输出 `{config, host}`；TTY 明确提示未登录且未启动服务。

### I-S02: 完善首次使用说明和回归证明

说明固定外部运行时的准备、显式信任与原生登录边界；补充生成、帮助、失败与已有命令兼容测试，保持包导出和发布文件范围。

### I-S03: 准备可审计的发布检查

消除“registry 查询失败即版本不存在”的推断，为获准版本提供 Actions 内的非发布可用性检查，准备版本元数据并运行完整检查。

通过 `check-version` 独立检查候选，不发布；与 `verify-version`
互斥。标签发布前复用同一失败关闭检查。实际安装验证覆盖原有入口、ESM 公共导出和新增 init，不依赖未发布的仓库模板；旧版本验证保持可用。

## Acceptance criteria

### I-AC01: 生成行为和安全边界可验证

测试证明生成配置有效、路径和声明明确、既有文件不变、敏感文件不被发现或复制，帮助与错误无网络和服务副作用。

### I-AC02: 既有能力和包形状保持

`pnpm check` 通过，保持原有 CLI、HTTP 与 VS Code 行为、`exports` 和
`files`；说明完整覆盖已安装包的首次使用。

### I-AC03: 发布检查失败关闭

版本存在时阻止发布；网络、HTTP 或无效元数据错误不能被当成版本空缺。获准版本为
`0.1.1-canary.20261106.1`，不引入长期令牌或本地发布。

当前证据及父验收修订记录见 [实施验证](Verification.md)。
