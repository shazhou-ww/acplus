# Deployment

现实验收必须在 `office-ubuntu`
执行，并包含未接触项目设计和实现上下文的独立 subagent 试用。用户已委托主 Agent 负责各门限审查，无须逐次询问；此授权不包含 npm 发布。

实际安装、独立首用过程及协调者复核见 [Ubuntu 实测证据](./Office-Ubuntu.md)。

## Steps

### D-S01: 验证实际安装入口

将准确候选提交构建的包安装到 `office-ubuntu`
的独立消费目录，不替换既有全局安装。检查两条命令的版本、帮助、安装来源与文件摘要；不执行 registry 发布。

### D-S02: 验证双入口真实使用

在专用测试工作目录与新建 Session 内执行真实 Agent 任务，不复制凭证或修改既有项目文件。优先复用设备已配置的受管服务与认证。

创建一个全新 subagent，仅提供 SSH 连接方式、候选入口所在 PATH、测试工作目录及任务目标；不提供设计文档、源码、命令示例、参数教程或既有测试结果。要求它自行发现
`acplus-ai`
帮助，列出 Agent、创建会话、提交只读任务、观察结果、读取事件，并验证缺少显式授权的删除会快速失败；最后验证显式删除仅移除本次测试历史。

记录首次帮助查询次数、后续发现调用、首次任务完成情况、错误/恢复、是否遇到输入等待及命令使用卡点。若发现产品缺陷，保留失败证据，退回实施修复后重新部署；新的盲测使用新的 subagent，不能用已获指导的同一实例冒充无上下文首用。

### D-S03: 核对交付与迁移指引

核对实际消费包随附文档与兼容说明，保存已脱敏的安装证据、盲测过程及结论。只清理本任务拥有的测试文件和服务，不影响设备已有安装、凭证或会话；保留可复查的隔离候选安装。若需发布，另获明确 tag 授权并遵循 Trusted
Publishing。

## Acceptance criteria

### D-AC01: 消费环境可发现两个入口

`office-ubuntu` 上的实际安装证据证明 `acplus` 与 `acplus-ai`
均可执行；提交、包摘要、版本及入口来源可核对，非仅本地源码调用通过。

### D-AC02: 真实流程无交互误入或历史分裂

全新 subagent 在没有项目上下文、没有命令教程及人工中途指点的条件下，仅凭公开帮助完成真实只读任务。端到端记录证明 AI 无 stdin 等待、输出可解析、两个入口共用会话，并能区分提交、等待与最终执行状态；明确记录失败与重试，不能只报告最终成功。

### D-AC03: 交付结果可追溯

保留候选提交、安装来源、独立 subagent 身份和受限提示、实际调用与结果及清理范围；主 Agent 根据证据批准准确部署修订。明确未发布 npm；若后续另行授权发布，再记录 Actions 及实际 registry 安装证据。
