# Deployment

状态：现实世界验收契约。使用主体世界已验证并同步的正式入口，本阶段不修改运行时代码、不发布 npm、不改变原有远端服务。

## Steps

### D-S01: 准备独立安装与认证环境

独立入口在主体世界完成切换前验证；本阶段验收切换后的正式入口，不再次引入旧接口兼容或自动迁移。

在显式选定的环境使用新的私有部署根目录、端口与专用 Agent
profile。安装确定版本的 ACP
Agent 和待验收软件包，按明确授权完成登录；不修改旧服务或复制其凭据，不执行 npm 发布。

目标为授权的 Ubuntu 环境，Node 24.22.2、Copilot CLI
1.0.107，使用显式已登录的专用 profile、独立 `/v2` 监听端口和 SQLite schema
2 数据根目录。安装源码提交 `79c69a7c31e371a1dd4da6eb6e9ea3ff466a526a`
的本地 tarball，SHA-256 为
`3b1ff6a05a31e8750c3a0cf4fde4f7255165bef54fb03ac165ec8e0c4fada55a`。版本字段不代表注册表新发布；以来源和哈希区分开发产物。

### D-S02: 验证真实 HTTP 执行与内容记录

通过 `/v2` 对独立 Copilot
CLI 提交真实执行，查询同一 Turn 的状态、消息和工具事件，并验证按 Turn 过滤。记录版本、身份与结果，不输出认证信息。

必须由安装后的正常 `.bin/ahplex`
命令启动服务，先确认版本/帮助可运行，再提交精确标记 `DEPLOY_OK`
的真实请求，验证真实文件读取的工具结果、过滤分页和重复同 ID 不再执行。

### D-S03: 验证离线读取与后端重启

停止 Agent 后重启 HTTP 服务，验证本地查询不启动后端；显式请求继续执行时验证已声明的恢复能力，以及不支持时的明确失败。检查原服务未受影响、所属测试进程已清理。

使用同一数据库和不可用的可执行文件证明本地读取产生 0 个 Agent 子进程；恢复原配置后继续同一 Session，检查重放不混入新 Turn。结束时确认数据根目录锁、profile 租约和所属进程均清理，保留历史与已授权 profile。

## Acceptance criteria

### D-AC01: 已安装软件包的直接 ACP 链路可用

外部环境通过新软件包的 `/v2`
完成真实 Copilot 执行，返回精确预期标记。以安装来源、版本、请求及同一 Turn 终态证明；不引用此前 AHPD 实验代替本次验收。

精确结果为 `DEPLOY_OK` 且
`state=complete`；工具事件必须来自真实文件读取，正式命令与公共库导出/依赖形态吻合，不含旧 AHP 运行时。

### D-AC02: 持久历史无需在线 Agent

服务重启且 Agent 不可用时，Session、Turn 与事件仍可查询，过滤结果只含目标 Turn。以真实 HTTP 响应及进程启动计数证明，明确部分记录与未归属事件。

### D-AC03: 恢复边界与隔离清理成立

认证查询只返回脱敏历史观测，重启或退出后不沿用已失效的成功状态；以受保护的认证 HTTP 流程、profile 复用和缓存失效对照证明，不暴露凭据。

继续执行保持同一后端会话或返回明确能力错误，不隐式重放；旧部署保持正常且无所属孤儿进程。以重启对照、能力证据和定向清理检查证明。
