# 设计决策与审阅上下文

本文件支持
[构想契约](Idea.md)，记录影响其结果和边界的设计选择，不定义第二份契约，也不增加独立验收标准。详细实现方案仍由主体世界逐步细化，并导出到项目文档。

## 为什么直接使用 ACP

产品目标是提供标准 HTTP 接口，按执行请求运行 Agent，并在 Agent 离线时查询持久会话内容，而不是统一 AHP 原生资源。独立 CLI 已提供 ACP，因此直接连接可以避免不必要的 AHPD 转换层。不能因此假设每个 ACP
Agent 都有相同的认证、并发或恢复能力。

这项选择不要求保留旧 AHP 接口语义，也不要求为 ACP 模拟 AHP
Chat。Agent 的原生 Session 就是会话；HTTP 资源使用独立、稳定的本地身份。

## 按需执行与离线查询

创建 Session 只保存本地元数据，首次执行才启动 Agent。只读查询来自已保存记录，不隐式启动、认证、恢复或查询后端。否则“Agent 停止后仍能查询”就无法成为可验证的产品能力。

记录只能证明服务曾经观察到的内容，应公开记录覆盖情况和观测时间。缓存可读不等于 Agent 可恢复；缺少原生恢复能力时明确失败，不创建替代会话或自动重放旧 prompt。

## Turn 与 Event 的关系

Turn 表示一次由请求发起的执行，Event 表示消息、工具或状态观测。每个 Event 必须属于一个 Session，关联零个或一个同 Session 的 Turn；一个 Turn 可以关联多个 Event。

查询事件可以按 Turn 过滤，也可以读取整个 Session。无法确认归属、历史重放或迟到的后台事件不能被强行归到当前 Turn。过滤不会改变原来的事件顺序与身份。

## 认证转接不等于管理 HTTP 用户身份

ACP 提供认证方法协商以及部分登录和退出原语，但不统一保证凭据存储、设备验证码输出或当前登录状态查询。因此由服务转接明确支持的流程，必要时使用 Agent 专用适配器。

凭据留在显式选定的 Agent
profile 或凭据库中；服务只缓存脱敏的方法、最近结果、验证时间和失效信息，不把认证密钥放进 Session、Turn 或 Event。历史登录成功不是永久有效的授权，运行时或 profile 变化、认证挑战、退出及已知过期都必须使当前证据失效。

缓存失效不必立即要求用户重新登录，但不能跳过后端认证检查，也不能隐藏发送付费模型请求来验证登录。调用方是否有权访问 HTTP 接口和使用某个 Agent，仍由外部网关及明确访问策略控制，不由共享的上游登录决定。

## 为什么先建立独立入口

不做旧接口兼容，但切换也不能破坏正在工作的旧服务。先在同包独立入口、配置和数据环境中验证新链路，通过自动测试与隔离真实 Agent 测试后，再直接替换旧入口并删除旧实现。临时共存只是验证和切换策略，不是长期双栈。
