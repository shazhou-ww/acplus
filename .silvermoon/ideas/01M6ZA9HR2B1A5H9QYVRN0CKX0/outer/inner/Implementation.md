# Implementation

状态：准备阶段的轻量实施初版，不属于构想验收范围；进入主体世界后逐步细化。已有讨论草案见
[中文版设计](../../../../../docs/ACP-DESIGN.zh-CN.md) 与
[英文版设计](../../../../../docs/ACP-DESIGN.md)，不将其视为已实现或已验收的证据。

## Steps

### I-S01: 细化并导出设计契约

在主体世界明确 `/v2`、schema
2、本地 Session/Turn 身份、Event 可选归属、按 Turn 过滤及分页、记录覆盖和故障语义。将设计细节同步导出到项目根级文档：
[README](../../../../../README.md)、[需求](../../../../../docs/REQUIREMENTS.md)、
[约束](../../../../../DESIGN-INVARIANTS.md)
和中英文设计文档；同步更新 HTTP/OpenAPI、CLI 与配置契约，清楚区分目标与实际实现。

### I-S02: 实现本地记录与直接 ACP 运行时

实现持久记录及纯本地读取，接入服务拥有的 stdio
ACP 进程。支持按需启动、显式 profile 认证、内容采集、精确执行关联和按能力恢复；不以缓存重放模拟后端恢复。

### I-S03: 完成切换与回归验证

接通 `/v2`
与 CLI/init，覆盖生命周期、并发、持久化和故障路径；验收新链路后移除旧 AHP 实现，不保留无用双协议抽象。保持单包发布形态，不在此步骤发布 npm 版本。

## Acceptance criteria

### I-AC01: 根级契约与设计一致

中英文设计、需求、约束、OpenAPI、CLI 和配置对身份、事件过滤及观测语义描述一致。通过契约测试和文档链接检查证明，目标描述不冒充已实现行为。

### I-AC02: 本地记录与离线读取正确

Session 创建和 GET 均不启动或调用 Agent，内容可跨服务重启读取。通过零启动测试、事件归属与过滤分页测试、存储故障注入证明；认证信息不进入记录或响应。

### I-AC03: 执行与故障语义可靠

ACP 初始化、prompt、事件、取消与能力门控恢复在 HTTP 链路中正确关联。通过协议模拟、崩溃与重复提交测试及
`pnpm check` 证明；未知结果不自动重放，不以旧 AHP 测试替代 ACP 验证。
