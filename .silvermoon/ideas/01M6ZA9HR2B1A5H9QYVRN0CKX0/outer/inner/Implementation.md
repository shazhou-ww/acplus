## Steps

### I-S01: 细化并导出设计契约

在主体世界明确 `/v2`、schema
2、本地 Session/Turn 身份、Event 可选归属、按 Turn 过滤及分页、记录覆盖和故障语义。将设计细节同步导出到项目根级文档：
[README](../../../../../README.md)、[需求](../../../../../docs/REQUIREMENTS.md)、
[约束](../../../../../DESIGN-INVARIANTS.md)
和中英文设计文档；同步更新 HTTP/OpenAPI、CLI 与配置契约，明确认证转接、非敏感观测缓存和失效边界，清楚区分目标与实际实现。

采用稳定 ACP wire v1 与官方 SDK 2.4.0，HTTP 版本为 `/v2`。配置 JSON
Schema 从实现导出，OpenAPI/HTML 使用同一契约。

### I-S02: 实现本地记录与直接 ACP 运行时

实现持久记录及纯本地读取，接入服务拥有的 stdio
ACP 进程。支持按需启动、显式 profile 认证、内容采集、精确执行关联和按能力恢复；实现独立于会话记录的认证观测缓存，不复制 Agent 凭据；不以缓存重放模拟后端恢复。

实现文件：[存储](../../../../../src/acp-store.ts)、
[运行时](../../../../../src/acp-agent.ts)、
[profile 租约](../../../../../src/acp-profile.ts)、
[服务](../../../../../src/acp-service.ts)。SQLite schema
2 明确拒绝较早开发格式；派发回调前不关联当前 Turn，已观察的后台歧义在实际 RPC 前被拒绝。

### I-S03: 完成切换与回归验证

先在同包独立入口中接通新实现，使用独立配置、数据、profile 和端口验证，保持旧入口不变；自动测试、已安装产物及隔离真实 Agent 测试通过后，直接提升为正常 CLI/库入口并删除旧实现。实现文件成为唯一正式入口，不保留额外临时命令、兼容层或长期双栈。

接通 `/v2`
与 CLI/init，覆盖生命周期、并发、持久化和故障路径；验收新链路后移除旧 AHP 实现，不保留无用双协议抽象。保持单包发布形态，不在此步骤发布 npm 版本。

## Acceptance criteria

### I-AC01: 根级契约与设计一致

中英文设计、需求、约束、OpenAPI、CLI 和配置对身份、事件过滤及观测语义描述一致。通过契约测试和文档链接检查证明，目标描述不冒充已实现行为。

### I-AC02: 本地记录与离线读取正确

Session 创建和 GET 均不启动或调用 Agent，内容可跨服务重启读取。通过零启动测试、事件归属与过滤分页测试、存储故障注入证明；认证密钥不进入会话记录或响应，认证查询只返回脱敏观测与新鲜度。

### I-AC03: 执行与故障语义可靠

最低 Node 22.13.0 与 Node
24 的 CI 全检查也必须通过；保留的 npm 安全测试应真正执行脚本的本地验证禁止逻辑，而不是因 TS 装载失败退出。

ACP 初始化、prompt、事件、取消与能力门控恢复在 HTTP 链路中正确关联。通过协议模拟、崩溃与重复提交测试及
`pnpm check`
证明；认证缓存随重启、profile 变化、退出、认证挑战或已知过期失效，不触发隐式付费探测或自动交互登录；未知结果不自动重放，不以旧 AHP 测试替代 ACP 验证。
