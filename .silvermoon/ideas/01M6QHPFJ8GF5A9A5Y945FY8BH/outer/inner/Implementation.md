# Implementation

本契约为准备阶段初版，构想验收不代表接受具体实现。复用现有 Host adapter 与官方 AHP SDK；独立 daemon 实验不能代替 AHPlex 全链路验收。

前置依赖：[softov/ahpd#246](https://github.com/softov/ahpd/pull/246) 修复了底层会话 ID 与 AHP Session ID 不同导致的重启恢复问题，已用修改后构建在 Ubuntu 验证。接入时锁定已验证修复构建或包含该修复的官方版本，不跟随浮动分支；必要时另行确定临时构建的供应方式。

## Steps

### I-S01: 接入受管 AHPD 主机

新增 AHPD adapter、静态配置与示例，首轮只接 Copilot CLI。主机拥有固定的数据目录、连接凭据和 agent profile；启动、协议就绪、重连、停止及清理遵循既有生命周期规则，不引入 ahpc 或第二套 ACP 转换。

### I-S02: 桥接原生登录交互

使用 Copilot CLI 的原生登录及凭据存储，展示必要的链接、设备码和存储确认。保持 TTY 与机器输出可用，区分主机就绪、登录状态与执行结果；不把登录退出码当成充分证据，不隐式发送付费探测 Turn，也不向 AHP 客户端复制用户 token。

### I-S03: 补齐恢复与兼容验收

通过现有 HTTP、CLI 接通 Session、Chat、Turn 全链路，覆盖数据目录复用、重连、历史恢复、准确取消、忙碌冲突及不确定结果处理。更新相关契约、配置和用户文档，保留 VS Code 既有行为；推荐配置切换以验收结果为前提，不迁移旧配置。若出现需要独立验收的交付，再拆子 idea，而非提前扩展任务树。

## Acceptance criteria

### I-AC01: 生命周期与配置有回归证明

测试证明并发启动合并、按需启动、就绪检测及仅清理自有进程；重连不创建重复 daemon，固定数据目录不会随重启重新生成，既有配置仍然有效。

### I-AC02: 登录不泄露或误报

测试覆盖成功、取消、超时、无 keychain 的显式选择及未知验证结果；状态、日志和 CLI 输出不包含凭据，主机就绪不等同于 provider 已登录，现有 VS Code 登录链路不回退。

### I-AC03: 原生资源与质量门槛保持

集成回归证明原 Session、Chat、Turn 身份及能力语义保持，断连不自动重放，已存在的不确定结果不能伪装成终态；`pnpm check` 通过，公共 exports 与 files 约束未被破坏。真实 Ubuntu 效果由部署契约另行验证。
