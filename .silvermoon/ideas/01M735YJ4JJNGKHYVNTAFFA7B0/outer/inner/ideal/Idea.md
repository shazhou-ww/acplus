# 重新设计 acplus CLI

## 问题

现有 CLI 把对话输入、资源配置与服务生命周期混在一起，命名和 ACP 能力发现也不够一致。需要先完成可追溯的设计讨论，再决定实施范围。

## 结果

形成面向 Agent 使用者的 CLI
Redesign 规格，明确单轮输入、Session 资源管理、身份认证及显式过桥服务管理。完整候选见
[CLI Spec](./CLI-SPEC.html)，确认记录与续接位置见
[讨论进度](./DISCUSSION.md)，需求模型见 [需求](./REQUIREMENTS.md)。

## 边界

- 本 Idea 当前仅讨论设计；不授权运行时代码修改、旧接口移除或发布。
- Human / AI 两入口共享业务能力，统一 JSON；本地执行与真实 ACP 能力边界明确。
- 保留显式授权、未知结果不重放、本地历史可读及用户文件与凭证隔离。

## 验收标准

- 命令树、参数、输出及场景模型一致，逐项确认状态可在规格与讨论记录中核对。
- 配置发现、异步受理、取消及服务管理的失败与不确定边界均有明确契约。
- 既有接口迁移和所有未决项完成确认或明确延期；完整设计未被局部批准冒充定稿。

## 下一步

从 `acplus agent auth-status` 继续逐章确认；最后完成共享契约与跨命令一致性复核。
