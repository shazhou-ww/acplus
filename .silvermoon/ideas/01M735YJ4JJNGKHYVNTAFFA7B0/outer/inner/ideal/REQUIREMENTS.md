# CLI Redesign 需求模型

本文是 [Idea](./Idea.md)
的理想世界支持文件，记录已经逐步确认的需求，不表示整份接口已定稿，更不表示运行时代码已实现。具体命令候选见
[CLI Spec](./CLI-SPEC.html)，确认范围与续接点见 [讨论进度](./DISCUSSION.md)。

## 1. 使用者与边界

唯一业务角色是 **Agent 使用者**。Human、AI
Agent、CI 是调用上下文，本地与 HTTP 是访问方式，不拆分额外业务角色；执行目标固定为本地环境。

一个包保留 `acplus` 与 `acplus-ai`
两入口，共用业务能力、身份、数据和服务。两个入口全部输出 JSON，不提供
`--json`；帮助和版本也没有文本例外。命令分组、交互方式仍可不同，统一输出格式不代表合并入口。

仅设计，不修改本项目运行时代码、HTTP 路由、存储 schema 或发布配置。新接口与旧接口的兼容迁移尚需明确批准。

## 2. 主场景清单

### S1: 与 Agent 开展工作

在已有 Session 中发送本轮输入，异步受理后查询执行与结果，继续同一工作上下文。提交受理不是执行完成；完成也不是用户目标必然达成。失败、取消与派发不确定必须区分，不自动重放未知工作。

Session 创建与发送是分开的操作。每条新用户消息创建新的 Turn，不能向原 Turn 追加用户消息；执行输出和工具观察可以持续产生。Turn
ID 由 CLI 自动生成、在派发前回执并在结果中返回，不是让用户或 AI 调用方手工分配的提交参数。查询和取消使用返回的确切 ID。重新调用发送是新的一轮，不是安全重试。

历史查询、取消、清理等是 S1 所产生资源的衍生管理场景，不再独立列为主场景。认证可能需要外部浏览器参与；不能用认证成功冒充模型执行成功。

## 3. 场景参数

以下 Y/N 分别表示产品默认与用户级配置的存在性，不表示必填：N/N 为本次操作专用值，N/Y 为可配置但无产品默认，Y/Y 为产品提供默认并允许用户、本次覆盖。条件参数只在对应操作适用。具体键、数值、输入编码属于接口讨论，未批准项见进度记录。

### 主场景

| 场景 | 参数         | 含义               | 产品默认值 | 用户级配置 |

## 4. 支撑资源

| 资源               | 归属与生命周期                                 | 管理需求与限制                                           |
| ------------------ | ---------------------------------------------- | -------------------------------------------------------- |
| Session            | 应用持久身份，绑定 Agent、身份环境和 workspace | 显式创建、列表、详情、改名、支持的配置修改、本地历史删除 |
| Turn               | Session 内单次提交与执行记录                   | 列表、详情、精确取消；不是可追加用户消息的容器           |
| 消息与事件         | 持久的消息、工具和状态观察                     | 分页及增量查询；含观察时间、来源和不完整性               |
| 已配置 Agent       | 用户配置的定义，不是运行进程                   | 定义与普通配置管理，身份关联另行管理                     |
| Agent 进程         | 应用按需持有                                   | 自动复用和安全退出，仅操作自有资源，未知不等于空闲       |
| 过桥服务           | 显式管理的本机运行实例                         | 后台启动、状态、停止；不自动拉起或空闲退出               |
| 身份环境与认证观察 | 凭证留在 Agent 专用环境，应用只保留安全观察    | 登录、状态、实际支持的退出；不显示凭证、无隐式付费验证   |

workspace 和 Agent 产生的项目文件是用户外部资源。删除会话不删除这些文件、Agent 配置或凭证，也不承诺删除后端原生历史。

### 会话建立与 ACP 能力发现

后续明确批准的替代行为：`session new`
异步受理后启动或复用 Agent，通过 ACP 初始化及 `session/new`
建立真实后端并记录绑定和实际
`configOptions`。这取代早先“创建只写本地元数据、不启动 Agent”的基线；不发工作 prompt、不自动登录、不执行付费验证。GET 仍只读，不以查询触发准备。

`setup: {state,error,observedAt}` 的 `accepted/ready/error/unknown`
四态已确认。ready 是绑定建立证据，不是 Agent 当前存活或凭证有效证明。未 ready 时拒绝 prompt
/ ACP 配置修改，不排队；准备中或结果未知拒绝删除。

`configOptions`
使用 Agent 实际公布的 ACP 描述，`id/name/type/currentValue`、适用的 `options`
及分组；名称和语义 category 不代替 ID。 `configOptionsObservation`
为本地新鲜度和观察时间，未知列表为 null。不发明固定模型列表、通用 token 硬限额或通用工具/目录权限策略参数。标准 ACP 权限请求如何在异步桥接中承接仍需讨论，不默认批准。

## 5. 辅助场景归并

| 类别              | 目标与可观察完成条件                                           |
| ----------------- | -------------------------------------------------------------- |
| A1 创建 Session   | 持久受理后建立真实 ACP 会话；可查询准备成功、明确失败或未知    |
| A2 管理 Session   | 发现、查看、逐项改名或改配置、删除本地历史；影响范围明确       |
| A3 观察与控制执行 | 获得安全的历史或确切取消受理，受理与终态区分                   |
| A4 普通配置       | 查询、单项保存和重置，区分用户来源、默认、unset 和实际运行生效 |
| A5 身份与认证     | 统一身份环境关联和认证生命周期，只展示安全元数据               |
| A6 服务管理       | 验证本机归属后显式启动/查询/停止，结果与资源释放有证据         |

同一资源的详情和配置查询合并；本地名称与 ACP 配置统一修改操作，但生效方式不同。批量对象修改已讨论后撤回，只保留逐项设置。

共享值按语义归并：创建默认 Agent /
workspace、列表查询数量、本机实例数据位置和启动监听地址。数据位置变化不迁移历史、不停止旧实例。身份配置与普通配置在逻辑上分离，不因共用文件而混为同一操作。

服务参考 Task
Engine 的显式后台生命周期与身份规则，而非复制其整个协议：实际目录单实例、运行身份校验、非 PID/端口猜测、状态无法核实则错误，默认有活动拒停，显式取消并停止才进入清理。重启不重放、未知仍为未知，不将参考系统的遗留任务统一失败规则套用于 ACP 执行。
