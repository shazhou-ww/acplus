需求追溯与边界

  1. 唯一业务角色：Agent 使用者；Human/AI/CI 是调用上下文，HTTP/本地是访问方式，执行环境为本地。
  2. 唯一主场景 S1：与 Agent 开展工作。先单独创建 Session，再明确指定 Session 与本轮输入异步发送。无默认日常会话。
  3. Session 绑定 Agent/目录并持有模型等配置，查询、更新、删除属于资源管理；工作区与产物是外部用户资源。
  4. 桥接服务显式后台启动、状态查询、停止；无业务触发启动、空闲退出、隐式当前实例或自动重放。Agent 进程仍按需管理。
  5. 普通配置、身份与认证、运行资源分开。认证方式由 Agent 真实能力决定，不采集通用密码/Token。模型按 Agent 公布选项管理，无通用 token 硬限额。

两个入口的全部输出统一使用 JSON，包括帮助与版本。新接口不提供 --json 开关；错误、日志与交互提示也不得退回纯文本。单轮发送不提供 --config、--url、--data-dir、--agent-id、--workspace、--model 或等待参数。没有新位置参数和同义别名。

草案使用固定用户配置 ~/.acplus/acplus.yaml；身份关联与普通配置可共用物理存储但由不同管理入口维护。业务命令从 app.dataDir 选择本地应用环境，不扫描最近启动实例。非默认实例启动参数不写回配置；要通过业务 CLI 使用该实例，须明确更新 app.dataDir，或外部客户端使用显式 HTTP 地址。

stdout、stderr、退出码（设计提案）

两个入口所有正常 stdout 统一为一份 JSON，不提供文本输出模式或格式切换参数；不增加全局 ok/data 包装。失败时 stdout 空，stderr 一行 {error:{code,message}}。日志、提交回执、警告及 Human TTY 确认提示均使用 stderr JSON Lines；普通进度禁入 stdout。统一格式不改变两套入口已确认的命令组织和交互边界。

JSON Lines 在实际输出中每个对象单行；示例为阅读展开。警告格式拟 {event:"runtime_warning",name,message}，不会把必读失败原因藏成日志。帮助与版本同样是 JSON，不存在文本例外。中断可没有最终 stdout，不能保证所有进程退出都有 JSON。

退出 0：成功观察、本地已提交变更或异步受理，不代表 Agent 工作成功。1：操作失败或状态无法核实。2：调用/输入错误。130：副作用提交前中断且清理已确认；发出请求后的中断结果不明则 1 并明确不确定。所有错误 code/message 可供程序读取，禁止成功形状的 unknown 服务状态。

帮助、TTY、输入与安全

根无参数打印帮助；Human 导航分组无参数打印组帮助，分组不是独立业务动作，无单独执行章节。叶子缺必需参数退出 2，不提示补齐。叶子 --help/-h 不访问配置/网络/身份；AI 根帮助包含完整命令、选项、结果与恢复说明，叶子帮助可以聚焦。

AI 从不读 stdin、readline、交互提示或打开 UI。Human 仅消息 --text-file - 可读 stdin；文件型 JSON 参数不接受 '-'。路径相对调用方解析，文件先校验大小和格式；不将 Agent 输入当命令。删除 Human TTY 可确认（提示为 stderr JSON Lines，如 {event:"confirmation_required",action:"session_delete",sessionId}），非 TTY 与 AI 必须 --yes；取消、配置写入与明确服务停止不二次提示。

Session/Turn 使用完整小写 UUID；名称非唯一、非选择器。无通用凭证读回、账号秘密参数、默认批准权限或自动登录。Agent 权限请求实际承接仍是未决交互问题，不因移除自有策略参数就默认允许。

异步受理、最终结果与不确定性

消息、登录、步骤答复、退出及 ACP 配置变更不等待 Agent 工作终态。纯本地元数据变更可返回已提交记录；服务 start/stop 等待各自就绪/释放证据，不能把后台运行误作生命周期操作无确认。此返回映射整体仍待共享契约批准，不新增通用队列或可重放任务。

业务写入要求已启动的本机桥接服务，未就绪明确失败，不自动拉起。普通配置/身份选择写入不需要启动服务；Session/Turn/事件及配置观察可离线只读。认证状态读取无 Agent 探测。IPC/HTTP 身份协议是内部实现，不是公开 API 重设计。

两个 CLI 的发送入口均自动生成 Turn ID，不接受调用者提供 ID；派发前向 stderr 输出带该 ID 的 JSON 回执，stdout 也返回它。每次新调用发送命令创建新的一轮，不是原轮次的安全重试。失去响应后只查询回执中的原 Turn 或会话轮次记录，不自动重发；不能凭相似文本猜测后再发送。服务层已有同 ID/同输入幂等保证保留，但 CLI 不提供手工提交 ID 的选项。unknown 保留，不当失败/完成/可重试。超时或 Ctrl+C 不自动取消。取消只向真实拥有者请求，受理不当已结束。

Session 修改本地名称不启动 Agent；ACP 配置写入仅在准备 ready 后按能力恢复已绑定后端，不静默新建且不发提示词。变更受理与已生效分开，latestChange 只在确有操作时返回其身份、state、错误和观察时间；确认后才更新已知配置。若修改结果不明，不伪造原子性、自动回滚或安全重试。

本机服务身份与所有权

实际数据目录逻辑唯一，运行 instanceId 每次启动不同；服务持有整个运行期独占所有权。别名路径、符号链接、目录联接指向同目录也冲突。PID/端口/锁文件均非充分身份。残留元数据和旧自有运行资源需核实；无法确认不删锁接管、不终止未知进程。

状态与停止无需抢占运行服务持有的锁，但必须校验当前身份；停止请求绑定识别实例，实例变化则失败。端口关闭、进程消失不等于已确认清理完成。普通 stop 有活动拒绝；显式取消并 stop 才停止新受理、处理活动并等待释放。无法核实的遗留派发不被改写成确定失败，不重放。

r5：异步受理与准备状态（已确认）

Session new 成功受理返回 sessionId、agentId、workspace、createdAt 和 setup；setup 为 {state,error,observedAt}。受理先持久保存，再进行真实 ACP 会话建立；本地受理退出 0 不等于后端已就绪。session get 返回同一 setup 观察及已知配置，读到 error/unknown 仍是成功读取，不隐式修复。

accepted
已受理且正在进行准备，不是持久任务队列，也不保证服务重启后自动恢复。
ready
真实 ACP Session 的绑定已确认且持久记录；不是 Agent 当前存活、凭证有效或业务执行成功的证明。Agent 不提供配置项时 configOptions 可仍为 null，并如实说明。

修改 Session 的生效与结果（逐项设置，已确认）

统一 session set：--name 只改本地非空展示名，可重复，不启动 Agent；--config-id 配合 --value JSON 或 --value-file FILE 修改 Agent 公布的配置，类型与选项值必须匹配，不要求用户填写变更 ID。一次调用只选择一种修改。

本地改名返回 {sessionId,name} 表示提交完成。ACP 变更异步返回 {sessionId,changeId,state:"accepted"}；changeId 自动生成。session get 的 configOptionsObservation.latestChange 记录 {changeId,configId,value,state,error,observedAt}，state 为 accepted/succeeded/error/unknown。succeeded 必须由 Agent 确认并持久记录，不能只改本地缓存；error 为明确失败，unknown 为结果不确定，不自动重提、回滚或冒充成功。

变更受理与结果写入已有 Session 事件，latestChange 只是便捷摘要，不替代历史；核对原回执 changeId，不能将另一变更的摘要当作本次结果。不增加通用任务或队列。准备未 ready、在途执行、配置变更未完成或结果不确定时，新的 ACP 配置修改拒绝而不排队；有活动/不确定变更时也不受理新的 prompt。Agent/身份/workspace 绑定不开放变更。

批量对象提案（已撤回）

用户明确要求恢复此前逐项设置。当前只保留 --name，或 --config-id 配合 --value/--value-file 的单项形式；不提供批量对象、configChanges、名称最后写入或部分成功状态。此处仅记录撤回，不形成第二套接口。

取消确切执行的 CLI 契约（已确认）

acplus session cancel --session-id UUID --turn-id UUID；AI 为 acplus-ai session-cancel。名字对齐 ACP session/cancel，但 --turn-id 是本地并发保护：必须核实这个 Turn 仍是指定 Session 的绑定执行，不能取消后来出现的另一轮。服务将本地 Session 映射为后端 sessionId，不把本地 Turn ID 冒充 ACP 原生参数。

请求受理返回 {sessionId,turnId,cancellation:"requested"}，不等执行结束、不启动替代 Agent；通过 turn get 查询真实终态。若已可靠确认目标 Turn 为 complete/cancelled/error，则不发送取消，返回 {sessionId,turnId,cancellation:"not-needed",state}，退出 0；只表示该轮无需取消，不表示整个 Agent 或所有后台工作都已停止。unknown、归属不明或目标绑定不匹配必须失败，不能当作幂等成功。

取消受理不当已结束；正常完成不能追改成取消。无服务时不自动拉起，不猜测杀进程、不删历史。请求发出后 Ctrl+C 不能撤销取消，响应丢失需查询核对而不是另选最新轮次。

删除本地 Session 的授权与边界（已确认）

Human 为 acplus session delete --session-id UUID [--yes]。显式 --yes 直接授权；未给时仅 stdin/stdout/stderr 均为 TTY 才能交互。确认提示用 stderr JSON Lines 的 confirmation_required 事件，列出目标与 yes/no，stdout 不混提示。非 TTY 与 AI 必须 --yes，否则输入错误退出 2，不读取 stdin 或持久记住授权。

确认 no、空输入或 EOF 明确拒绝删除，stdout 空，stderr 返回 confirmation_declined，退出 1；其他无效答复报输入错误；不重复提示。未发送请求前中断可退出 130。请求发出后中断不能撤销已发生的删除，只能报告可核实结果或不确定，不能谎称未删除。

删除只清理明确 Session 的本地元数据、Turn、消息事件及所属配置变更观察；返回 {sessionId,deleted:true} 仅在本地清理提交后成立。准备中、准备结果未知、有活动或不确定执行/配置变更时拒绝，不提供强制绕过。目标不存在明确报错，不补造本次删除成功。

不启动 Agent，不删用户项目、Agent 配置或凭证；不承诺删除 Agent 自有后端历史。服务须已启动，不以删除代替取消。

消息事件分页与增量读取（已确认）

acplus event list --session-id UUID [--turn-id UUID] [--after N] [--limit N]；AI 为 acplus-ai event-list。仅查询已提交的本地事件，--after 默认 0，取 sequence 大于 N 的记录，N 为 0..9007199254740991；limit 沿用 query.limit。Turn 筛选在分页前进行，序列仍属于 Session 全局，稀疏正常；没有 Turn 筛选时包含会话级配置变更等事件。

返回 items、nextAfter、lastSequence、coverage、observedAt。nextAfter 非 null 时用于继续当前分页；null 仅表示当前没有下一页，不证明未来不会新增。lastSequence/coverage/observedAt 属于当前查询范围；指定 Turn 时是该轮的最后已知观察，不是整个 Session 的末尾。读完当前分页后，下一次增量查询保留单调位置，使用 max(已有 after,lastSequence)，不因过滤范围的水位较小而回退；未读完分页前不能跳到末尾。

Event 含 sessionId、可空 turnId、sequence、type、payload、source、observedAt；明确区分消息/工具/应用状态等来源，不将本地事件冒充原始 ACP 通知。配置变更历史以 changeId 关联，通常属于 Session 而无 Turn；限定 Turn 时不会返回这些事件。只返回安全的持久观察，不含凭证或原始认证转录。

不启动服务或 Agent、不长轮询、不自动翻完全部页面；缺失或不完整历史通过 coverage 表达，不能伪装成完整空历史。会话或所筛选的 Turn 不存在时明确报错，不用空数组替代。

普通配置查询结果与缺失边界（已确认）

acplus config get [--key KEY]；AI 为 acplus-ai config-get。未给 key 查询全部普通配置，给 key 查询已知单项；未知键报输入错误。返回 {items:[{key,value,source}]}，source 为 user/product/unset：用户覆盖、产品默认或无配置且无默认。unset 时 value:null 明示缺失，不编造 Agent 或会话默认值。

只读用户保存的普通配置与产品定义，不创建缺失配置文件/数据目录，不启动或探测服务/Agent。用户配置文件不存在时合法显示产品默认及 unset；已存在但格式损坏或未知项不能默默回退默认，必须报错。Agent 定义只返回非敏感部分，不解析凭证引用、不读取或输出秘密，身份认证观察由 agent auth-status 管理。

普通配置的单项保存与生效（已确认）

acplus config set --key KEY (--value JSON | --value-file FILE)；AI 为 acplus-ai config-set。一次设置一个已知普通配置项；值按该项的类型与约束校验，Agent 定义本身可为对象，但不提供跨多个配置键的批处理。不接受 '-' 文件输入或身份秘密，身份关联由 agent identity-set 管理。

acplus-ai server-stop [--data-dir PATH] [--cancel-running]

适用 公共参数与配置、流与退出码、交互与安全、异步与不确定性。本章特例：不另行提示，--cancel-running 是本次明确动作。请求发出后 Ctrl+C 不能撤回停机；已知与不确定结果必须如实报告。

参数

acplus-ai server-stop 参数
名称 类型与输入来源 必需性 草案默认 用户配置映射 约束与冲突
--data-dir PATH 命名参数／目录 否 草案：~/.acplus/state app.dataDir 实际目录标识逻辑实例；相对目录从调用方工作区解析。
--cancel-running 命名参数／明确动作选择 仅选择取消并停止时 普通停止 不允许持久默认 改变动作目的，不是第四类普通参数；无此选择且有活动则拒停。

预期输出与影响

stdout
始终单个 JSON 结果。 本次停止 {state:"stopped",dataDir,instanceId,changed:true}；无需停止 {state:"not-started"|"stopped",dataDir,changed:false}，后者不补造本次释放证据。
stderr
错误为一行 {"error":{"code":"...","message":"..."}}；日志不混入 stdout。普通成功没有进度输出。
退出码
0 成功观察、提交受理或本章已核实的变更；1 操作失败或无法核实；2 输入错误；130 仅本次尚未提交副作用且已核实清理的中断。0 不保证 Agent 工作成功。
资源影响
冻结新受理，仅处理自有资源；取消执行、认证及会话准备等活动需确认结束，未知则不报成功。保留配置、凭证、历史及项目文件。
帮助／终端／取消
--help/-h 无副作用并退出 0。缺失必需参数退出 2，不以提示补参数。即使 TTY 也不读 stdin、不提示、不打开 UI。 不另行提示，--cancel-running 是本次明确动作。请求发出后 Ctrl+C 不能撤回停机；已知与不确定结果必须如实报告。
