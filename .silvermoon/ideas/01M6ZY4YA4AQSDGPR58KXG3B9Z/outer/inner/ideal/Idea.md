# 自动管理本地 server 生命周期

## 问题

当前历史查询和执行命令都要求用户先运行 server，给脚本和日常 CLI 使用增加了后台进程管理负担。

## 结果

本地 sessions/turns/events 历史查询无需 server；执行所需服务由 CLI 按需启动或复用，在无执行工作且空闲一段时间后自动退出。

## 边界

- 显式 URL（含 ACPLUS_URL）仍只访问指定服务；显式 serve 保留常驻模式。
- 不新增“Session 已全部完成”的语义，不以历史状态冒充实时状态；详见[行为边界与决策依据](Behavior.md)。
- 保持单写者、历史持久性、取消真实性和结果不明不重放的[现有约束](../../../../../../DESIGN-INVARIANTS.md)。

## 验收标准

1. 服务未运行时可读取已提交历史，查询不启动进程或改写数据。
2. 无显式 URL 的本地创建与执行无需手动 serve，连续或并发命令能安全复用服务。
3. 自动服务不打断执行，空闲后可退出并再次按需启动；显式常驻和远程访问行为保持不变。
